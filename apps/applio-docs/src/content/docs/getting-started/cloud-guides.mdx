Cloud workflows run the Python engine on remote hardware. They do not install the Electron desktop window in a notebook. A path in a cloud interface refers to the remote machine, not your local computer.

## Google Colab

The project provides an [Applio No UI notebook](https://colab.research.google.com/github/IAHispano/Applio/blob/main/assets/Applio_NoUI.ipynb) and a [Gradio UI notebook](https://colab.research.google.com/github/IAHispano/Applio/blob/main/assets/Applio.ipynb).

<Aside type="note">
  Check the [Colab FAQ](https://research.google.com/colaboratory/faq.html) for current runtime limits and permitted usage. Access to GPUs and web interfaces depends on the service and account; a notebook link does not guarantee availability.
</Aside>

<Steps>

1. Open the notebook and read its setup and usage notes.
2. Select an appropriate runtime if one is available.
3. Run installation cells in order, then verify the environment.
4. Upload or mount your recordings and models. Use paths on the remote runtime.
5. Run the desired conversion or training cells.
6. Save results and checkpoints to persistent storage before ending the session.

</Steps>

For a UI notebook, use the connection method currently offered by its launch cells. Tunnel providers, authentication, and limits can change; follow the notebook's output rather than old fixed credentials or rate-limit claims.

## Kaggle and other notebooks

Use a notebook that explicitly supports the provider you choose. Check accelerator availability, internet permissions, dataset paths, and session limits in that provider's current instructions.

Upload data through its supported dataset/file workflow, then supply the remote folder path to Applio. Mounts may be read-only; place training outputs in a writable working directory. Keep tunnel tokens private.

## Preserve training work

Back up the full experiment folder, not only the inference export. Include training checkpoints, configuration, feature files, and the original dataset needed to continue.

To resume, restore the experiment into the new runtime, use compatible architecture/sample-rate/embedder settings, and set an epoch target above the completed epoch. Avoid fresh/cleanup options when continuing.

A disconnected browser does not prove the remote process has stopped. Check the notebook's status before starting another run. Copy important files to persistent storage regularly; temporary runtime storage can disappear.

## Bring results back to Desktop

Download the exported `.pth` and matching `.index`, then [upload them in Desktop](/getting-started/installing-inference-models/). Copy full experiments separately if you want to continue training locally. Performance and package support can differ between cloud and local hardware.
