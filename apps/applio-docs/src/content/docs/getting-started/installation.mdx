## Manual Installation

<Tabs>
  <TabItem label="Windows">
    <Steps>
      1.  Download the latest precompiled `.zip` file from [Hugging Face](https://huggingface.co/IAHispano/Applio/tree/main/Compiled/Windows).
      2.  Extract the archive to a simple path on your `C:` drive (e.g., `C:\Applio`).
      3.  Run the `run-applio.bat` file to start Applio.
    </Steps>
    <Aside type="caution" title="Important">
      -   Make sure the installation path does not contain spaces or special characters.
      -   Temporarily disable your antivirus or firewall if it interferes with the installation.
      -   Do not run the installer as an administrator.
    </Aside>
  </TabItem>
  <TabItem label="Linux/macOS">
    <Tabs>
      <TabItem label="Option 1: Git Clone">
        <Steps>
          1.  Clone the repository from GitHub:
              ```bash
              git clone https://github.com/IAHispano/Applio.git
              cd Applio
              ```
          2.  Run the installation script:
              ```bash
              chmod +x run-install.sh
              ./run-install.sh
              ```
          3.  Launch Applio:
              ```bash
              chmod +x run-applio.sh
              ./run-applio.sh
              ```
        </Steps>
      </TabItem>
      <TabItem label="Option 2: Manual Python Installation">
        <Steps>
          1.  Clone the repository from GitHub:
              ```bash
              git clone https://github.com/IAHispano/Applio.git
              cd Applio
              ```
          2.  Set up a Python virtual environment and install dependencies manually. See the **Detailed Setup for Linux/macOS** section below for instructions.
        </Steps>
      </TabItem>
     <Aside type="note" title="First-Time Setup">
        If you encounter issues, you may need to install Python 3.10.12 and create a virtual environment. See the **Detailed Setup for Linux/macOS** section below for instructions.
     </Aside>
    </Tabs>
  </TabItem>
</Tabs>

## Advanced Installation & Guides

This section contains advanced installation methods and guides for specific hardware.

### AMD GPU Support (Windows)

If you have an AMD GPU, you can set up Applio with Zluda for hardware acceleration.

<Tabs>
  <TabItem label="1. Install Dependencies">
    <Steps>
      1.  Download and install the [VC++ Runtime](https://aka.ms/vs/17/release/vc_redist.x64.exe).
      2.  Verify your GPU meets the [System Requirements](https://rocm.docs.amd.com/projects/install-on-windows/en/develop/reference/system-requirements.html).
      3.  Install the appropriate HIP SDK version from the [AMD ROCm Hub](https://www.amd.com/en/developer/resources/rocm-hub/hip-sdk.html) for your GPU.
    </Steps>
  </TabItem>
  <TabItem label="2. Install Applio">
    <Steps>
      1.  Download and extract the Applio v3.2.5+ precompiled version.
      2.  Open a command prompt in the Applio folder and run the following commands to install the correct PyTorch version:
          ```cmd
          env\python -m pip uninstall torch torchvision torchaudio
          env\python -m pip install torch==2.3.1 torchvision==0.18.1 torchaudio==2.3.1 --upgrade --index-url https://download.pytorch.org/whl/cu118
          ```
    </Steps>
  </TabItem>
  <TabItem label="3. Configure Zluda">
    <Steps>
      1.  Move all `.bat` files from the `assets\zluda` directory to the root Applio folder.
      2.  Run the appropriate patch script for your HIP SDK version (`patch_zluda_hip57.bat` or `patch_zluda_hip61.bat`).
      3.  Add the `bin` directory of your HIP SDK installation to your system's Path environment variable.
      4.  Run `run-applio-amd.bat` to start Applio.
    </Steps>
    <Aside type="note" title="Initial Compilation">
      The first time you run Applio with Zluda, it will compile kernel code, which can take 15-20 minutes. The application may appear frozen during this time.
    </Aside>
  </TabItem>
</Tabs>

### AMD GPU Support (Linux)

If you want to use Applio with an AMD GPU on Linux, the general approach is to install the **ROCm** stack for your distribution, make sure your user can access the GPU, verify that ROCm detects the card, and install a ROCm-compatible PyTorch build inside Applio's virtual environment.

<Tabs>
  <TabItem label="General ROCm setup">
    <Steps>
      1.  Install the ROCm packages for your Linux distribution using the official AMD/ROCm documentation for your distro.
      2.  Add your active user to the `render` and `video` groups, then reboot or log out and back in.
      3.  Verify that ROCm can detect your card with `rocminfo`.
      4.  Activate Applio's virtual environment, remove the stock PyTorch packages, and install a ROCm-compatible build that matches your GPU architecture.
    </Steps>
    <Aside type="note" title="GPU Architecture">
      ROCm support depends on the GPU architecture target, such as `gfx1032` for some Radeon RX 6000-series cards. 
      Check the [AMD GPU architecture reference](https://rocm.docs.amd.com/en/latest/reference/gpu-arch-specs.html) before installing a custom wheel.
    </Aside>
  </TabItem>
  <TabItem label="Example: Nobara + Radeon RX 6650 XT">
    <Aside type="note" title="Nobara uses a custom bundled package for ROCm."> Source: https://wiki.nobaraproject.org/graphics/amd/opencl-rocm-support</Aside>
    <Steps>
      1.  Install ROCm on Nobara with:
          ```bash
          sudo dnf install rocm-meta
          ```
      2.  Add your user to the required groups:
          ```bash
          sudo usermod -a -G render,video $USER
          ```
      3.  Verify the group membership and reboot:
          ```bash
          grep 'render' /etc/group
          ```
      4.  Verify that ROCm recognizes your GPU:
          ```bash
          rocminfo
          ```
      5.  In the Applio folder, activate the existing virtual environment and install a ROCm-compatible PyTorch build:
          ```bash
          source .venv/bin/activate
          pip uninstall torch torchvision torchaudio -y
          ```
          If your AMD GPU is not on the officially supported ROCm list, you may be able to use a community-maintained nightly build such as [TheRock](https://github.com/ROCm/TheRock). For a GPU with architecture `gfx1032`, the following example can work:
          ```bash
          pip install --index-url https://rocm.nightlies.amd.com/whl-multi-arch/ "torch[device-gfx1032]" "torchvision[device-gfx1032]" torchaudio
          ```
    </Steps>
  </TabItem>
  <TabItem label="Troubleshooting">
    <Tabs>
      <TabItem label="Known MIOpen Issues">
        <Steps>
          1.  If you encounter MIOpen-related errors during startup or model loading, this is a known issue in some ROCm and PyTorch combinations.
          2.  As a workaround, disable MIOpen in the file that launches Applio (commonly `app.py`) by adding:
              ```python
              # Disable MIOpen
              import torch
              torch.backends.cudnn.enabled = False
              ```
          3.  If the application still fails, confirm that ROCm can see your GPU (`rocminfo`), that the correct PyTorch build is installed, and that the architecture target matches the wheel you installed.
        </Steps>
      </TabItem>
      <TabItem label="Terminal Errors?">
        Some terminal messages after enabling ROCm can be ignored if Applio still starts and serves the local URL.
        The key sign is that Applio launches successfully and you see a local URL such as `http://127.0.0.1:6969`.
       
        <Aside type="note" title="Example of inconsequential output">
          After enabling ROCm, the terminal may show warnings such as:
          ```bash
          E-001h rocSHMEM Could not open libnuma. Returning       NUMAWrapper@src/gda/numa_wrapper.cpp:48
          An error occurred connecting to Discord: Could not find Discord installed and running on this machine.
          * Running on local URL:  http://127.0.0.1:6969
          * To create a public link, set `share=True` in `launch()`.
          kf.kio.gui: Not passing environment variable "BASH_FUNC__module_raw%%" to systemd because its name contains illegal characters
          kf.kio.gui: Not passing environment variable "BASH_FUNC_ml%%" to systemd because its name contains illegal characters
          kf.kio.gui: Not passing environment variable "BASH_FUNC_module%%" to systemd because its name contains illegal characters
          ```
          These messages are often inconsequential if Applio still launches successfully.

          -   `E-100h rocSHMEM could not open libnuma...`: This is related to ROCm's multi-GPU clustering support and typically only matters if you are using multiple GPUs. If you are not running a multi-GPU setup, you can usually ignore it.
          -   `kf.kio.gui: Not passing environment variable...`: This is specific to KDE Plasma and happens when the desktop environment blocks certain shell function names from being synced into the system session. It is not harmful and does not affect Applio's ability to run.

        </Aside>
      </TabItem>
    </Tabs>
    <Aside type="caution" title="Experimental Support">
      Some AMD GPUs only work through community-maintained builds such as [TheRock](https://github.com/ROCm/TheRock), especially when the card is not listed in the [official ROCm support matrix](https://rocm.docs.amd.com/projects/rocm-support-matrix/en/latest/). 
      Expect some trial and error, and verify each step against the AMD and distro-specific documentation.
    </Aside>
  </TabItem>
</Tabs>

### Manual .venv Setup for Linux/macOS

If the manual installation for Linux/macOS fails, you may need to set up a virtual environment manually.

<Tabs>
  <TabItem label="Debian/Ubuntu">
    <Steps>
      1.  Ensure you have Python 3.10 installed.
      2.  Open a terminal in the Applio directory and run:
          ```bash
          sudo apt install python3.10-venv -y
          python3.10 -m venv .venv
          source .venv/bin/activate
          # Continue with installation steps inside the virtual environment
          ```
    </Steps>
  </TabItem>
  <TabItem label="Arch Linux">
    <Steps>
      1.  Ensure you have Python 3.10 installed.
      2.  Open a terminal in the Applio directory and run:
          ```bash
          sudo pacman -S python-virtualenv --noconfirm
          python3.10 -m venv .venv
          source .venv/bin/activate
          # Continue with installation steps inside the virtual environment
          ```
    </Steps>
  </TabItem>
</Tabs>

### Docker Deployment

Applio provides official Docker images for both CPU and GPU (CUDA) deployments.

<Steps>
1.  **Install Docker:** Follow the [official Docker installation guide](https://docs.docker.com/get-docker/) for your operating system. For GPU support, install [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
2.  **Clone the repository:**
    ```bash
    git clone https://github.com/IAHispano/Applio.git
    cd Applio
    ```
3.  **Build the Docker image:**
    -   For CPU: `docker build -f Dockerfile -t applio:cpu .`
    -   For GPU: `docker build -f Dockerfile_cuda -t applio:cuda .`
4.  **Run the container:**
    -   Using Docker Compose: `docker compose up`
    -   Or manually: `docker run --gpus all -p 6969:6969 applio:cuda`
5.  **Access Applio:** Open `http://localhost:6969` in your browser.
</Steps>

<Aside type="tip">
  Docker is an excellent option for server deployments, cloud environments, and ensuring consistent dependencies across different systems.
</Aside>

## Updating and Uninstalling

**To update Applio**, we recommend deleting the current Applio folder and reinstalling using your preferred method, but be sure to back up any desired data first! Here are the most common desired data locations:
- `assets/audios`: Audio you have uploaded, and the inference results.
- `logs`: Inference models you have downloaded or trained, plus some other stuff that comes with Applio.
- `rvc/models/pretraineds/custom`: Any pretrained base models you have downloaded.
<Steps>
  1. Move or copy the above folders out of the `Applio` folder, if they contain something you want to keep.
  2. Delete the entire `Applio` folder, then install the new version.
  3. Move the above folders back into their correct locations in the new `Applio` folder. Merge folders with the same names, but do not overwrite files that came with both Applio versions. This should mean choosing to "merge" or "write into" folders with the same names, but choosing to "skip" files with the same names.
</Steps>

**To uninstall Applio**, simply delete the Applio folder.
