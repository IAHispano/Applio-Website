Choose one installation route, finish its setup, and then test one voice model. You do not need to install both interfaces.

| What you want to do | Start here |
| --- | --- |
| Use the dedicated desktop app | [Applio Desktop](#applio-desktop) |

For your first test, have a short voice recording ready. You will add an inference voice model after setup; installing the interface alone does not select a voice for conversion.

## Applio Desktop

Download a build for your operating system from the [official App releases](https://github.com/IAHispano/Applio-App/releases). Read its release notes for platform requirements and known issues.

<Tabs>
  <TabItem label="Windows">
    Run the Windows setup executable as your normal user. Choose a folder you can write to: the packaged Windows app stores its runtime and user data in a `data` folder beside the executable.
  </TabItem>
  <TabItem label="macOS">
    Choose **arm64** for Apple Silicon or **x64** for Intel. Open the disk image and install the app. Consult the release notes if macOS blocks it from opening.
  </TabItem>
  <TabItem label="Linux">
    Choose an available Linux package. Allow an AppImage to run as an executable before launching it; install a Debian package with your distribution's package manager.
  </TabItem>
</Tabs>

### Finish engine setup

<Screenshot src={desktop.setup} alt="Desktop setup progress showing Python environment preparation, dependency installation, model assets, and verification" caption="Setup prepares the environment, installs dependencies and assets, and verifies the installation. Keep Applio open while the stages finish." interfaceName="Desktop 1.0.7" />

<Steps>

1. Open Applio and review the terms shown on first run.
2. Let automatic setup finish. If your build offers **Install / Repair**, use it when setup or a dependency check needs to be retried. Keep the app open while it prepares Python, engine packages, and required assets.
3. Wait for setup verification to finish before opening a conversion job. If a check fails, read the first failure in the setup log, address that issue, and retry **Install / Repair**.
4. Open **Models** and [add an inference voice model](/getting-started/installing-inference-models/). Then follow [your first file conversion](/getting-started/inference/#convert-your-first-file).

</Steps>

The desktop download contains the interface and engine code. First-run setup installs the environment needed to run the engine; it requires internet access and can take time. Audio separation may install extra packages and download models on first use.

<Aside type="note">
  Installing a release does not require Node.js or pnpm. Those tools are for building Desktop from source.
</Aside>

### Check that setup is complete

If setup is still running, leave it open rather than starting repeated conversion jobs. If it stops with an error, keep the log and follow [setup troubleshooting](/getting-started/report-error/#common-problems). A successful installation is the starting point; a short conversion confirms that your model and audio workflow also work.

### Hardware and dependencies

| Component | What to check |
| --- | --- |
| GPU | Setup's detected hardware and engine status. NVIDIA CUDA, supported AMD configurations, and Apple MPS have different requirements. |
| Memory | Try a short file first. Training and realtime need different amounts of memory and compute. |
| Disk | Space for the environment, models, datasets, checkpoints, and outputs. |
| FFmpeg | Setup status, especially if loading or exporting audio fails. |
| Network | Setup, downloads, and Edge TTS need internet access. Downloaded voice models can be used for local conversion. |

Use the repair workflow before changing PyTorch manually. Old CUDA or HIP/ZLUDA recipes may conflict with the environment chosen by the current app.

## Python application with Gradio

Applio with Gradio runs locally and opens its interface in your browser. On Windows, you can use the compiled package from Hugging Face. The [Applio repository](https://github.com/IAHispano/Applio) also provides source installation, CLI, and cloud workflows.

<Tabs>
  <TabItem label="Windows">

    **Compiled version**

    1. Download a compiled Windows `.zip` from [Applio on Hugging Face](https://huggingface.co/IAHispano/Applio/tree/main/Compiled/Windows).
    2. Extract the entire archive into a folder you can write to.
    3. Run `run-applio.bat` from the extracted folder and open the local address printed in the console. Keep the console open while using Applio.

    The compiled package includes its Python environment. Follow any additional instructions included with your chosen build.

    **From source**

    If you prefer a source checkout, clone or download the repository, run `run-install.bat`, then run `run-applio.bat`.
  </TabItem>
  <TabItem label="Linux / macOS">

<Command shell="bash" command={"git clone https://github.com/IAHispano/Applio.git\ncd Applio\nbash run-install.sh\nbash run-applio.sh"} />

    Current scripts target Python 3.12. Follow the requirements shipped with your chosen release.
  </TabItem>
</Tabs>

### Confirm Gradio is running

<Steps>

1. Keep the launch process open and wait for it to print a local browser address.
2. Open the printed address, rather than assuming a fixed port. Check that the interface finishes loading.
3. Open **Models** and [add a voice model](/getting-started/installing-inference-models/), then [convert a short file](/getting-started/inference/).

</Steps>

Closing the launch process stops the local service; an open browser tab does not keep it running. If no address appears, read the terminal error before retrying. If the page opens but a job fails, collect the job error and terminal log.

Keep the launch process running while using Gradio. In its Python environment, `python app.py --help` lists server options. [Cloud notebooks](/getting-started/cloud-guides/) have their own setup.

### Containers

The Python repository includes Dockerfiles and Compose configuration. Read those files for your chosen revision before building: GPU access, ports, and persistent volumes are deployment choices. Keep datasets, models, and outputs outside an ephemeral container.

## Build Desktop from source

The [App README](https://github.com/IAHispano/Applio-App#development) specifies Git, Node.js 22+, pnpm 11, Python 3.12, and FFmpeg.

<Command shell="bash" command={"git clone --recurse-submodules https://github.com/IAHispano/Applio-App.git\ncd Applio-App\npnpm install\npnpm desktop:dev"} />

If the engine submodule is missing, run `pnpm backend:init`. Complete setup in the interface. `pnpm dev` starts the App browser UI and API; `pnpm typecheck` checks TypeScript; `pnpm build:all` builds its packages.

## Update or uninstall

**Desktop:** use the update controls in **Settings** or install an official newer build. Finish or stop active work before restarting. Updating the interface and repairing engine dependencies are separate operations.

**Gradio:** back up data before replacing a release. In a source checkout, preserve local changes and read release instructions before updating code and dependencies.

Save outputs and back up models, datasets, training checkpoints, custom assets, and preferences. See [storage and migration](/guides/moving-to-desktop/) for locations. Uninstalling the program and deleting its user data are separate decisions.
