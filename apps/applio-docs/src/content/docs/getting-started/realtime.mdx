**Realtime inference** has many of the features of regular file-based inference, because at the core it is using the model in much the same way. The main difference is that it can work on a live audio stream instead of just a pre-recorded file. This makes it useful for humor or scambaiting.

## How to Perform Realtime Inference

<Steps>
  1.  **Select an Input Device:** Click the drop-down device menu in the **Input Device** panel, and select one.
  2.  **Select an Output Device:** Same song, second verse, this time in the **Output Device** panel.
  3.  **Switch to the Model Settings tab.**
  4.  **Select Your Model:** Choose the `.pth` and `.index` files for your model. If you don't see your model in the list, click the refresh button.
  5.  **Start the engine:** Click the large **Start** button at the top of the page. It may take a moment to load, but you should soon see some fluctuating **Latency** readings. Keep an eye on the console for errors.
  6/  **Shuttind down:** When you are done, click the same button again, now labeled **Stop**, to stop the engine.
</Steps>

<Aside type="note">
  Applio uses Python PortAudio as the backend for connecting to audio devices. If you are having trouble getting your desired device(s) to show up, it is probably a limitation of PortAudio. You may have success in looking up how to make your device show up for it, however.
</Aside>

## Additional settings

### Audio settings

- **Gain:** All three audio devices (**Input**, **Output**, and **Monitor**) have a gain slider to adjust their volume:
  - **Input gain** should be adjusted if you encounter distortion from input clipping, or if the model seems to have a hard time hearing you (i.e. it only produces output when you are being very loud).
  - **Output gain** can be adjusted to the requirements of any audio application you might be piping into (e.g. Discord, OBS Studio, etc).
  - **Monitor gain** can be adjusted to your tastes.
- **Monitor Device (Optional):** Useful for when you want the converted audio piped into another application, but you also want to hear it. *Before* starting the realtime inference engine,
  <Steps>
    1.  **Enable the feature:** Click the **Use Monitor Device** checkbox.
    2.  **Select a device:** Click the **Monitor Device** drop-down menu, and pick a device that is *not* the same as the **Output Device**.
    3.  **Continue preparing for engine start.**
  </Steps>
- **Record Audio (Optional):** While realtime inference is running, you can record the output to a file.
  <Steps>
    1.  **Choose an output path, if desired:** This isn't really necessary, as you will have a chance to download the file elsewhere, and is also restricted to Applio's allowed paths, but you can set an **Output Path** other than the default if you want. The biggest use for this is to correct the output file extension to match the **Export Format** that you select. It can also be used to prevent Applio from overwriting `assets/audios/output.wav`.
    2.  **Choose an export format:** Applio defaults to saving the recorded audio as Microsoft uncompressed Wave PCM, but you can choose to save it as lossy ultra-compressed MPEG-3, compressed Free Lossless Audio Codec, or lossy compressed ultra-seekable OGG. Note: If you choose something other than WAV, you must manually change the file name extension yourself in the **Output Path**.
    3.  **Begin recording:** Once the realtime engine is *already running*, click the big **Start** button in the **Record Audio (Optional)** panel to begin recording. Click it again later to **Stop**.
  </Steps>
- **Enable VAD:** This is essentially the VOX setting on a two-way radio, only running inference when Applio detects that you are actually talking. This saves CPU power only intermittently, so it won't help for gaming on the same machine, but it might help improve battery life or thermals.
