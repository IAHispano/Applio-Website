Realtime converts microphone audio in small blocks. Its latency includes capture, processing, buffering, and playback. A GPU that can convert files may still be too slow for your chosen realtime settings.

Use headphones while monitoring to prevent feedback.

## First, verify the model with a file

Complete a [short file conversion](/getting-started/inference/#convert-your-first-file) using the voice model and embedder you plan to use live. If that fails, fix model/setup problems before introducing microphone permissions, device routing, and latency settings.

For the first live test, use headphones and a simple local route. Confirm that Applio can convert your microphone before connecting a chat or streaming app.

## Start a session

<Tabs>
  <TabItem label="Desktop">

<Screenshot src={desktop.realtime} alt="Desktop realtime workspace and its configuration panels" caption="Select a model and your audio devices before starting a live session. Device controls stay unavailable until microphone access is granted." interfaceName="Desktop 1.0.7" />

<Steps>

1. Finish setup, add a model, and open **Realtime**.
2. Allow microphone access. Select **Input Device** and **Output Device**; refresh devices if a newly connected device is missing.
3. Choose your voice model, matching index, and embedder.
4. Start streaming and wait until the model is ready before speaking.
5. Enable **Hear myself** if you want local monitoring. Adjust monitor volume.
6. Stop the session when finished.

</Steps>

Desktop captures and plays audio through its browser audio layer. Device availability depends on operating-system permissions and browser support. Model and audio settings can apply while streaming; wait for the applied status before judging a change.

### Check the local session

Speak a short phrase at your normal volume and leave a brief pause. With monitoring enabled, confirm that you hear the converted voice without feedback, missing words, or repeated interruptions. Local monitoring is a listening check; it does not prove that another application is receiving the converted audio.

If nothing is audible, check the selected input, output, monitoring control, and input level first. If the original voice is passing through in Desktop, check whether **Passthrough** is enabled. For broken audio, follow [latency tuning](#tune-latency) before adding another application.

## Send the voice to another application

To use converted audio in a chat or streaming application, route Applio's output into a virtual audio device, then choose that device's receiving end as the other application's microphone. Applio does not install a system-wide virtual microphone.

<Steps>

1. Confirm that the simple local session above works, then stop it before changing the route.
2. Set up a virtual audio device using that tool's own installation instructions. Identify its playback side and receiving/recording side; their names vary by tool and operating system.
3. Keep your physical microphone selected as Applio's input. Select the virtual device's playback side as Applio's output.
4. In the chat or streaming application, select the virtual device's receiving side as the microphone. Do not leave the physical microphone selected there if you want the converted voice.
5. Start the Applio session, then make a short recording or microphone test inside the receiving application. Listen back to that recording to verify which voice arrived.
6. Check levels at the destination and remove any duplicate physical-microphone route that creates echo.

</Steps>

If Applio monitoring sounds correct but the destination recording does not, troubleshoot the route and the destination's selected input before changing the voice model. If both sound broken, return to the simple local test.

## Tune latency

| Control | Effect |
| --- | --- |
| **Chunk Size** | Smaller chunks can reduce delay but leave less time for processing. Increase it if audio drops or breaks up. |
| **Auto chunk size** | Lets Desktop choose a block size; use it as a starting point where available. |
| **Crossfade Overlap Size** | Smooths transitions between blocks. More overlap adds context and work. |
| **Extra Conversion Size** | Includes past audio as context. Larger values increase memory and processing cost. |
| **Enable VAD / Silence Threshold** | Controls voice activity handling. A threshold that is too high can cut off quiet speech. |
| **Input Gain** | Changes the level reaching conversion. Reduce it if the input clips. |
| **Output Gain / Monitor volume** | Changes playback level; check the destination recording as well as local monitoring. |

### Tune one variable at a time

<Steps>

1. Keep the model, test phrase, and device route fixed. Use automatic chunk sizing as a starting point where available.
2. Speak for several seconds and watch the latency/diagnostic readings. Judge stable audio, not just the smallest displayed number.
3. If audio drops out or delay grows, increase chunk size first and test again. Reduce optional effects or extra context if needed.
4. Once playback is stable, try a smaller chunk size only if you need less delay. Return to the last stable setting if interruptions come back.
5. Repeat the destination microphone test after changing the route or important audio settings.

</Steps>

Test with normal speech for several seconds after a change. Reduce optional effects and extra context before pushing chunk size lower. The diagnostic and calibration controls in Desktop can help identify unstable buffering.

The pitch, embedder, retrieval ratio, and protection controls follow the [conversion guide](/getting-started/inference/#understand-the-main-settings). Precision options depend on hardware and decoder support.

## Passthrough, recording, and the tray

Desktop's **Passthrough** sends unconverted microphone audio. Configure its hotkey if you need to switch quickly. Tray controls let you manage realtime while the main window is minimized.

Start streaming before starting a recording. Stop recording, then save or download the result. In Gradio, check the recording output path and export format together.

<Aside type="note">
  Realtime shares GPU resources with conversion and training. In Desktop, an active GPU job prevents realtime from starting, and queued GPU jobs wait while realtime owns the GPU. Stop the session before starting other GPU work.
</Aside>

## If audio fails

- **No devices:** check microphone permissions and refresh devices.
- **No output:** check the selected playback device, receiving application, monitor controls, and VAD threshold.
- **Feedback:** use headphones and remove any route feeding output back into the input.
- **Dropouts or growing delay:** increase chunk size, reduce extra context and effects, and stop other GPU workloads.
- **Engine disconnect:** inspect realtime logs and setup diagnostics, then restart the session.

See [troubleshooting](/getting-started/report-error/) for reporting a reproducible failure.
