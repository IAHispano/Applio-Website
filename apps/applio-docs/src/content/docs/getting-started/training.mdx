Training learns a voice from recordings. Dataset quality, coverage, and compatible settings matter more than simply increasing epochs.

## Plan a first training run

Start with a new experiment and one reviewed dataset. Keep a short recording out of the training data so you can compare saved models using a voice sample the run has not learned from.

Your first goal is to complete preprocessing, feature extraction, training, and an inference test. Do not choose a large epoch target or reuse an old experiment just to get started. If you only want to use an existing voice, [add an inference model](/getting-started/installing-inference-models/) instead.

| Decide before starting | Why it matters |
| --- | --- |
| A distinct experiment name | Keeps this run separate from previous checkpoints and features. |
| Dataset location and speaker layout | The engine must read the intended files on its host computer. |
| Architecture, rate, pitch configuration, and G/D pair | These must be compatible before training can begin. |
| Exact embedder choice | The trained model needs the same feature representation at inference. |
| Where to keep checkpoints and a held-out test clip | Lets you compare progress and resume without starting over. |

## Prepare the dataset

Use clean recordings of the intended speaker with varied phrases, pitches, and delivery. Keep original recordings and work on copies. See [dataset preparation](/guides/how-create-datasets/).

In Desktop, upload audio through **Training** or select a dataset path on the computer running Applio. Gradio commonly uses folders under `assets/datasets`.

For multiple speakers, preserve numeric subfolders:

### Review recordings in Desktop

Use the dataset review controls to scan recordings, listen to flagged clips, and choose what to include. You can prepare a training copy with silent-edge trimming, level balancing, and peak headroom, then select **Use this dataset for training**.

A scan is a starting point for listening. Reducing peaks cannot recover audio already damaged by clipping.

## Choose compatible settings

| Setting | How to choose |
| --- | --- |
| **Model Name** | A distinct experiment name. Reusing a name can reuse existing training artifacts. |
| **Sampling Rate** | Match the architecture and G/D pretrainings. Desktop exposes 32, 40, 44.1, and 48 kHz where supported; not every combination supports all four. |
| **Vocoder** | HiFi-GAN, MRF HiFi-GAN, or RefineGAN as offered by your interface. Applio-specific architectures may not load in other RVC clients. |
| **Embedder** | Record the exact choice and custom path. Use it again during inference. |
| **Pretrained G/D** | Use a compatible pair matching the architecture, sample rate, and pitch configuration. |
| **Batch Size** | Choose a value that fits available VRAM. Reduce it if training runs out of memory. |
| **Total Epoch** | A stopping target, not a quality guarantee. Compare held-out conversions at saved checkpoints. |
| **Save Every Epoch / Save Every Weights** | Keep periodic checkpoints and inference exports for comparison and recovery. |

Preprocessing resamples recordings to the training rate; input files do not all need to start at that rate. Resampling cannot create missing high-frequency detail.

### Automatic training

<Steps>

1. Open **Training**, set the model name, hardware, and compatible model settings.
2. Choose **Automatic Training** and select or upload the dataset.
3. Review epochs, batch size, and advanced options.
4. Select **Start Automatic Training** once and follow its job console. Keep the app open while the pipeline is working.
5. Check which stage is running. Preprocessing and extraction must finish before training can use their outputs.
6. When the pipeline finishes, inspect the reported artifacts. If index generation was set to **Skip**, there will not be a new retrieval index from that run.
7. Continue with [the first inference test](#test-your-first-export) before deciding whether to train longer.

</Steps>

### Manual training

Choose **Manual Training Setup** to run the stages separately:

<Steps>

1. Open **Preprocess Dataset** and use **Run Preprocess**. Confirm the dataset path and sampling rate, then wait for successful completion.
2. Open **Extract Features** and use **Run Extraction** with the intended pitch method and embedder. Wait for the extraction job to finish.
3. Open **Model Training** and use **Start Training** after reviewing the compatible G/D pair, batch size, epochs, and save settings.
4. Use **Generate Index** when you want retrieval data for this experiment. Keep the index with the inference model from that experiment.

</Steps>

Changing a preprocessing or extraction setting may require rerunning downstream stages.

### Check each stage before continuing

| Stage | What to verify | If it does not finish |
| --- | --- | --- |
| Preprocess | The log shows that usable recordings were read and processed. | Check the dataset path, supported audio, and whether the intended clips were included. |
| Extract | Pitch/content extraction finishes for the experiment with the chosen embedder. | Read the first failing extraction message; check the embedder assets and available memory. |
| Train | Epoch progress advances and checkpoints or weights are saved according to your settings. | Check configuration compatibility and the job error. For memory failures, reduce batch size before retrying. |
| Export / index | You can identify the inference export and any generated index. | Check save/export settings and whether index generation was skipped or failed. |

Stop at the failing stage and keep its log. Do not start later manual stages with missing or stale inputs. If you change the dataset, sampling rate, or embedder, rerun the affected preparation stages before training on the new configuration.

## Monitor quality

Open [TensorBoard](/getting-started/tensorboard/) for training metrics, and convert the same held-out clips with saved models. A lower total loss alone does not prove better voice quality. Listen for intelligibility, pitch stability, timbre, and artifacts.

For memory errors, reduce batch size, disable dataset caching in GPU, or try checkpointing where supported. Stop realtime before starting a Desktop GPU training job.

## Export your model

Desktop provides **Models**, under **Export**; Gradio has export controls in its training workflow. Export the inference `.pth` and its matching `.index` if generated.

Keep `G_*.pth` and `D_*.pth` training checkpoints if you want to resume. A small inference export does not contain the full state needed for continuation.

## Test your first export

<Steps>

1. Open **Convert Audio** and select the inference `.pth` exported from this experiment, not a `G_` or `D_` training checkpoint.
2. Match the training embedder and choose the correct speaker ID if the model contains multiple speakers.
3. Use the held-out recording, keep pitch and optional effects consistent between comparisons, and run a short conversion.
4. Listen for intelligibility, stable pitch, the intended timbre, and artifacts. Keep the output with a note of which checkpoint or export produced it.
5. Compare another saved export on the same clip before choosing more epochs. Prefer the model that sounds better on the test material, rather than assuming the latest is best.

</Steps>

If the export cannot load, check compatibility and artifacts first; more training will not fix the wrong file type or an embedder mismatch.

## Resume training

Use the same experiment name, architecture, sample rate, embedder/features, and compatible checkpoint files. Set a new total-epoch target above the completed epoch. In Desktop, leave **Fresh Training** off when continuing a project.

Before starting the continuation, check the completed epoch in the existing run and confirm the new target is higher. Watch the first resumed log messages to confirm that the intended checkpoint is loaded. If it starts from an unexpected state, stop and inspect the experiment rather than overwriting more files.

Back up the entire experiment before changing its settings. Fresh/cleanup options are intended for a new run, not continuation. See [storage and backups](/guides/moving-to-desktop/).
