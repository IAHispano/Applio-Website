Applio uses **retrieval-based voice conversion (RVC)**. A recording supplies the content and performance; a trained generator synthesizes it with another voice's characteristics. Retrieved features can reinforce the target timbre.

## File-conversion pipeline

~~~text
Input audio
  → mono audio at 16 kHz for analysis
  → content features + pitch (when enabled)
  → optional feature retrieval and blending
  → speaker-model synthesis
  → model-rate audio, optional cleanup/effects, export
~~~

### Audio and content features

The file path loads audio at **16 kHz** for analysis. The embedder extracts frame-level content features; this is separate from the model's synthesis rate, which can be 32, 40, 44.1, or 48 kHz depending on architecture and support.

An embedder is not the speaker voice model. Feature dimensions and representation must match what the generator was trained to accept. Use the training embedder during inference.

### Pitch

For models with pitch guidance, a predictor extracts F0. The engine applies pitch adjustment according to:

~~~text
adjusted F0 = extracted F0 × 2^(semitones / 12)
~~~

Positive values raise pitch; negative values lower it. Autotune modifies the extracted pitch before synthesis. Proposed pitch can add a calculated offset toward a configured target.

Available predictors vary by interface and release. The current Desktop conversion controls expose RMVPE, FCPE, CREPE, and Swift.

### Retrieval

Training feature vectors are stored in a **FAISS index**. The file pipeline searches for eight nearest neighbors and constructs a retrieved feature representation using distance-based weights.

**Search Feature Ratio** controls blending:

~~~text
blended features = ratio × retrieved features + (1 − ratio) × input features
~~~

It does not change the neighbor count. Retrieval is skipped when no usable index is selected or its influence is zero.

KMeans can reduce the feature set before the engine builds the FAISS index. The resulting `.index` is still a FAISS index.

### Synthesis and protection

The generator receives content features, speaker ID, and pitch information where supported. Vocoder choices exposed by Applio include **HiFi-GAN**, **MRF HiFi-GAN**, and **RefineGAN**. Their architectures and pretrained weights are not interchangeable.

For pitch-guided conversion, unvoiced protection blends original features into unvoiced sections. In the current file engine, this branch runs below a protection value of 0.5; lower values retain more original unvoiced features.

The output is synthesized at the model/output rate. Long-file segments can be combined, then noise reduction and optional effects applied before export. Formant processing belongs to the input-loading path; it is not simply another output effect.

## Training pipeline

1. **Preprocess:** slice, resample, and optionally filter, normalize, or reduce noise.
2. **Extract:** compute pitch and content features for the recordings.
3. **Train:** optimize generator and discriminator networks.
4. **Export:** save a compact generator model for inference.
5. **Index:** build retrieval data from extracted features.

Training uses losses for adversarial behavior, feature matching, mel reconstruction, and latent regularization. The generator produces audio; a mel spectrogram of that audio contributes to reconstruction loss. The discriminator is used during training, not inference.

The engine includes distributed training support. Whether a configuration can use it depends on hardware and runtime support.

## Files and compatibility

| Artifact | Contents and purpose |
| --- | --- |
| Exported inference `.pth` | Generator weights, model configuration, and available metadata such as rate, F0 flag, embedder, vocoder, epoch, and speaker count |
| Training G checkpoint | Generator training state used for continuation or initialization |
| Training D checkpoint | Discriminator training state |
| `.index` | FAISS retrieval data built from extracted features |
| Experiment folder | Configuration, extracted data, checkpoints, event logs, and exports |

The file extension does not identify the checkpoint schema. An inference export cannot replace the complete experiment for resuming training. Standard RVC clients may not support Applio-specific architectures.

## Realtime is a separate path

Realtime maintains rolling audio context and processes blocks. It resamples, extracts features, synthesizes, aligns adjacent output, and applies overlap/crossfade handling. Voice activity and buffer settings affect behavior and latency.

Desktop captures and plays audio through browser AudioWorklets and sends blocks to the Python realtime service through WebSockets. Gradio also has a native audio-device workflow. See [realtime setup](/getting-started/realtime/) for user instructions.

## Desktop and the engine

Desktop has a React/Next.js interface, an Express gateway, and an Electron shell. The App pins the Python engine as a Git submodule and adds runtime adapters, job management, setup, and native controls.

The App also exposes an **`applio` CLI launcher**. It selects a Python interpreter and forwards engine commands to the App's `core.py` adapter; running it without arguments in an interactive terminal opens a menu. See the [CLI reference](/reference/cli/#launch-the-app-cli) for launchers and examples.

File conversion normally uses a persistent Python worker to reuse loaded state. Training runs engine scripts. Realtime runs its own Python service and reserves GPU access against queued jobs.

For implementation details, read the [Applio engine source](https://github.com/IAHispano/Applio) and [App source](https://github.com/IAHispano/Applio-App). Match documentation to the release you use: the App's pinned engine revision can differ from standalone Applio.
